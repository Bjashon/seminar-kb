# Seminar KB — памятка для агентов

Двуязычная (RU/EN) база знаний по докладам семинара по неассоциативным алгебрам: определения, теоремы, свойства из статей, связанные между собой; доска статьи; тренажёр; рабочие страницы исследовательских проектов. Отдельный проект, с Draftea не связан ни кодом, ни базой, ни деплоем.

Владелец пишет по-русски — отвечать по-русски. Она сама не программирует: объяснять результат, а не код.

## Устройство

- `backend/` — FastAPI + SQLAlchemy + Alembic. Локально SQLite (`backend/dev.db`), на проде Postgres.
- `frontend/` — React + Vite + MathJax. В проде бэкенд сам раздаёт собранный `frontend/dist`.
- `backend/app/ingestion/extracted/*.json` — весь контент (одна статья = один файл). Общие понятия, не относящиеся ни к одной статье (алгебра Грассмана, теорема Пуанкаре–Биркгофа–Витта), — в `glossary.json` там же.
- `backend/app/ingestion/talks_metadata.json` — снимок метаданных докладов из Notion.
- `data/sources/<код доклада>/` — PDF для панели источника. `data/raw/` — выгрузка Notion, есть только локально, **не трогать**.
- `projects/<slug>/project.md` — страницы исследовательских проектов, вкладка «Статьи» в приложении.

## Добавить статьи

Перед любой работой с контентом прочитать **[docs/adding-talks.md](docs/adding-talks.md)** — там весь процесс, формат JSON и правила, каждое из которых появилось из реальной ошибки. Коротко:

```
cd backend
./.venv/Scripts/python.exe -m app.ingestion.list_talks --season 7 --todo   # что ещё не разобрано
./.venv/Scripts/python.exe -m app.ingestion.validate_extracted             # проверка JSON, 0 errors
./.venv/Scripts/python.exe -m app.ingestion.load_entities                  # загрузить в локальную базу
```

## Исследовательские проекты (вкладка «Статьи»)

Проект — файл `projects/<slug>/project.md`: первая строка `# Название`, дальше обычный markdown с формулами (`$…$`, `$$…$$`), заголовками `##`, списками. Названия понятий из базы в тексте сами становятся ссылками на карточки. Обсуждение идёт в чате, итоги (постановка задачи, решения, следующие шаги, журнал с датами DD/MM/YYYY) записываются в `project.md` и коммитятся. Черновики и выкладки проекта — рядом, в той же папке. Сейчас есть проекты «Герстенхабер» (`projects/gerstenhaber/`, статья) и «Скобочные тождества (задача 2.6)» (`projects/monomial-identities/`, открытая задача из «Днестровской тетради»; скрипты счёта в `checks/`, им нужен `python-flint`, которого в `.venv` нет; перед работой над задачей читать `START-HERE.md` в папке проекта — там состояние, прочитанная литература и следующий шаг).

Внизу страницы проекта показываются его файлы — блоками, с подписью к каждому файлу. Блоки и подписи описаны в `projects/<slug>/files.json`; новый файл нужно туда вписать, иначе он попадёт в безымянный блок «Остальное». Папки `papers/` и `scratch/` на страницу не выводятся.

Если в папке проекта лежит `lecture.html`, на его странице появляется кнопка курса (`frontend/src/lecture/`); её подпись — поле `label` в `lecture.json`, по умолчанию «Лекция по статье». В `lecture.html` — текст курса, в `lecture.json` — тесты, карточки для повторения, глоссарий и данные вычислителей. Формулы там пишутся обычным TeX, без своих макросов: в MathJax приложения их нет.

Общая часть курса (оглавление, прогресс, тесты, карточки) — `lecture/mount.ts`; вычислители у каждого курса свои, в `lecture/labs/`, и выбираются полем `labs` в `lecture.json` (`gerstenhaber`, `brackets`). Новый набор вычислителей нужно добавить в таблицу `LABS` в `mount.ts`. Математика вычислителей проверена: `lecture/core.ts` — на тождествах статьи про Герстенхабера, `lecture/trees.ts` — тестом `projects/monomial-identities/checks/trees.test.mjs` (`node …/trees.test.mjs .` из корня репозитория); если их менять, проверку нужно повторить.

## Проверка и деплой

- Команды Python — через `./.venv/Scripts/python.exe` (на Windows голый `python` может быть заглушкой Store).
- Изменения интерфейса проверять в браузере, а не только сборкой: `cd frontend && npm run build`, затем `./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000` из `backend/` и открыть http://127.0.0.1:8000. Для автоматической проверки годится `playwright-core` с системным Edge (`chromium.launch({ channel: "msedge" })`).
- Телефон. Под узкий экран (до 700px, конец `index.css`) подогнаны только верхняя полоса и тренажёр. Дашборд, указатель и страницы проектов на телефоне владелец просила не трогать — их вид там менять нельзя без её просьбы. Изменения тренажёра и полосы проверять и в размере телефона: в playwright — `viewport: { width: 390, height: 844 }, isMobile: true, hasTouch: true`; ничто не должно быть шире экрана, верхняя полоса должна остаться высотой 53px. На телефоне каждая новая карточка тренажёра встаёт сразу под верхнюю полосу, а переключатель колод и счётчик остаются выше, их видно при прокрутке вверх (так просила владелец; `spot`/`placed` в `Trainer.tsx`). Серая подсказка под карточкой там скрыта, а слишком широкие выключные формулы уменьшаются, но не мельче 3/4 (`fitFormulas`).

Определения на карточках пишутся формально: каждое условие — формулой с кванторами, без рассуждений вокруг («это самое общее…», «интуиция», «измеряет, насколько…»). Так просила владелец, увидев многословное определение алгебры. Две выключные формулы подряд — одним блоком `aligned`/`gathered`.
- Тренажёр помнит место в каждой колоде («Базовые понятия», каждая статья, «Мой набор») на сервере, чтобы телефон и компьютер продолжали с одной карточки: таблица `deck_progress` хранит карточки, уже пройденные в текущем круге (`/review/decks` в `api/review.py`, `deckKey` в `Trainer.tsx`). Так же хранятся отметки курсов — «Модуль пройден», ответы на тесты, пометки на карточках курса: таблица `course_state`, `/projects/<slug>/lecture/state` (изменения шлются по одному действию и сливаются на сервере). Копия курса на claude.ai сервера не видит и хранит то же в браузере (`mount.ts`: параметр `storage`, по умолчанию `localStorage`). У сайта один пользователь; всё, что должно быть одинаковым на её устройствах, хранить в базе, а не в браузере.
- Миграции схемы — только через Alembic (`backend/alembic/versions/`), при старте контейнера они применяются сами.
- Деплой: пуш в `master`, затем владелец вручную жмёт **Redeploy** в EasyPanel. Автодеплой не работает (GitHub webhook → 403); это принятое решение, чинить его без её просьбы не нужно. После пуша всегда напоминать про Redeploy.
- Не коммитить, пока не попросили или пока это не часть оговорённой задачи; перед коммитом смотреть `git status`.
