# Seminar KB — памятка для агентов

Двуязычная (RU/EN) база знаний по докладам семинара по неассоциативным алгебрам: определения, теоремы, свойства из статей, связанные между собой; доска статьи; тренажёр; рабочие страницы исследовательских проектов. Отдельный проект, с Draftea не связан ни кодом, ни базой, ни деплоем.

Владелец пишет по-русски — отвечать по-русски. Она сама не программирует: объяснять результат, а не код.

## Устройство

- `backend/` — FastAPI + SQLAlchemy + Alembic. Локально SQLite (`backend/dev.db`), на проде Postgres.
- `frontend/` — React + Vite + MathJax. В проде бэкенд сам раздаёт собранный `frontend/dist`.
- `backend/app/ingestion/extracted/*.json` — весь контент (одна статья = один файл). Общие понятия, не относящиеся ни к одной статье (алгебра Грассмана, теорема Пуанкаре–Биркгофа–Витта), — в `glossary.json` там же.
- `backend/app/ingestion/talks_metadata.json` — снимок метаданных докладов из Notion.
- `data/sources/<код доклада>/` — PDF для панели источника. `data/raw/` — выгрузка Notion, есть только локально, **не трогать**.
- `projects/<slug>/project.md` — страницы исследовательских проектов, вкладка «Статьи» в приложении.

## Добавить статьи

Перед любой работой с контентом прочитать **[docs/adding-talks.md](docs/adding-talks.md)** — там весь процесс, формат JSON и правила, каждое из которых появилось из реальной ошибки. Коротко:

```
cd backend
./.venv/Scripts/python.exe -m app.ingestion.list_talks --season 7 --todo   # что ещё не разобрано
./.venv/Scripts/python.exe -m app.ingestion.validate_extracted             # проверка JSON, 0 errors
./.venv/Scripts/python.exe -m app.ingestion.load_entities                  # загрузить в локальную базу
```

## Исследовательские проекты (вкладка «Статьи»)

Проект — файл `projects/<slug>/project.md`: первая строка `# Название`, дальше обычный markdown с формулами (`$…$`, `$$…$$`), заголовками `##`, списками. Названия понятий из базы в тексте сами становятся ссылками на карточки. Обсуждение идёт в чате, итоги (постановка задачи, решения, следующие шаги, журнал с датами DD/MM/YYYY) записываются в `project.md` и коммитятся. Черновики и выкладки проекта — рядом, в той же папке. Сейчас есть проекты «Герстенхабер» (`projects/gerstenhaber/`, статья) и «Скобочные тождества (задача 2.6)» (`projects/monomial-identities/`, открытая задача из «Днестровской тетради»; скрипты счёта в `checks/`, им нужен `python-flint`, которого в `.venv` нет; перед работой над задачей читать `START-HERE.md` в папке проекта — там состояние, прочитанная литература и следующий шаг).

Внизу страницы проекта показываются его файлы — блоками, с подписью к каждому файлу. Блоки и подписи описаны в `projects/<slug>/files.json`; новый файл нужно туда вписать, иначе он попадёт в безымянный блок «Остальное». Папки `papers/` и `scratch/` на страницу не выводятся.

Курсы на сайте не показываются (так решила владелец 20/10/2026: без лектора читать неудобно, сайт — в основном для карточек). Курс живёт только на claude.ai; на странице проекта вместо него ссылка «Лекция на claude.ai ↗» (или «Курс…», если в `lecture.json` есть `label`) на `claude_url` из `lecture.json`, в новой вкладке. `lecture.html` (текст курса) и `lecture.json` (тесты, карточки для повторения, глоссарий, данные вычислителей) — исходник копий на claude.ai, их собирают `projects/gerstenhaber/artifact/build_artifact.py` и `projects/monomial-identities/checks/build_artifact.py`. Формулы там пишутся обычным TeX, без своих макросов.

Курс 2.6 собирается из кода `frontend/src/lecture/`: общая часть (оглавление, прогресс, тесты, карточки) — `mount.ts`, вычислители — `labs/`, выбираются полем `labs` в `lecture.json`; новый набор нужно добавить в таблицу `LABS` в `mount.ts`. В сборку сайта этот код не входит. У курса про Герстенхабера вычислители свои, в `artifact/template.html`; `lecture/labs/gerstenhaber.ts` и `lecture/core.ts` — их прежняя версия для сайта. Математика вычислителей проверена: `lecture/core.ts` — на тождествах статьи про Герстенхабера, `lecture/trees.ts` — тестом `projects/monomial-identities/checks/trees.test.mjs` (`node …/trees.test.mjs .` из корня репозитория); если их менять, проверку нужно повторить.

### Курсы на claude.ai и карточки из них

У курсов есть копии на claude.ai (ссылка — `claude_url` в `lecture.json`) с панелью «Спросить лектора». В копиях работает «набор карточек» — общий модуль `artifacts/picks.js`. Владелец выделяет в тексте слово, формулу или утверждение и жмёт «＋ В карточки» — или вписывает своё в поле «Написать самой» в панели набора (фрагмент с пометкой `own` и модулем, который она читала; кнопка набора видна и при пустом наборе). Свой текст Claude формализует и, если в нём ошибка, пишет верную формулировку и одной фразой говорит в «Пояснении», что исправлено. В наборе Claude (capability `sample`) пишет из фрагментов карточки: формальная формулировка плюс абзац «*Пояснение.*». «Отправить на сайт» открывает `<сайт>/#import=<код>`, «Скопировать код» — вставка через кнопку «Карточки из курса» на странице проекта.

- Сайт сначала показывает карточки (`ImportCards.tsx`), а добавляет только по кнопке: `POST /cards` (`api/cards.py`), с пометкой `entities.made_by_user`. Куда — выбирает она:
  - в колоду курса (псевдодоклад `proj_<slug>`, при нужде создаётся);
  - в «Мой набор» (без колоды, с закладкой);
  - в любую готовую колоду;
  - в свою новую тему — доклад-колода `my_<n>` с её названием, в списке тренажёра подписан «моя тема»; то же название ещё раз — та же тема. Свои темы и колоды курсов (`proj_`) стоят в «По статьям» первыми, блоком «Мои темы и курсы»: без даты они иначе уходили в самый низ, и владелец их не находила.
- `load_entities` такие карточки не трогает. Тренажёр берёт их любого вида, включая теоремы. Удаляются они из тренажёра: `DELETE /entities/<slug>`, только свои.
- Набор, адрес сайта и прогресс курса копия хранит в своей `db` (`data/users/<id>/picks`, `.../progress`), поэтому нужны capabilities `sample`, `db`, `user`.
- Свои TeX-сокращения курса (`\Z`, `\rp{…}` из конфигурации MathJax) модуль раскрывает: на сайте их нет.

Копия курса 2.6 собирается `projects/monomial-identities/checks/build_artifact.py` и подключает `picks.js` сама. Копия курса про Герстенхабера собирается `projects/gerstenhaber/artifact/build_artifact.py` из `lecture.html` и `lecture.json` проекта, в своём дизайне «тетрадь / доска» (`artifact/template.html`): `SEMINAR_SITE_URL=<сайт> ./backend/.venv/Scripts/python.exe projects/gerstenhaber/artifact/build_artifact.py . <out.html>`, потом Artifact publish по `claude_url`, без capabilities. Адрес сайта — только через переменную, в репозиторий его не писать. Подсказки «Спросить лектора» по модулям — поле `suggest` в `lecture.json`. Новый курс на claude.ai получает тот же модуль `picks.js`.

Как писать текст курса (владелец требовала это жёстко, 20/10/2026): курс рассказывает, а не перечисляет. Каждое понятие определено до первого использования; каждая выкладка — по строкам, с правилом на каждом шаге; примеры досчитаны до конца; никаких «очевидно», «как известно», «аналогично», «запомни»; короткие абзацы, без сплошных блоков текста. В модуле сначала вся теория, вопросы и задачки (с решениями) — в конце. Варианты ответов в тестах движок не перемешивает, поэтому верный ответ ставить на разные места. Ловушка MathJax: «[» в начале строки сразу после `\begin{aligned}` или после `\\` читается как параметр и пропадает — писать `{}[`.

## Проверка и деплой

- Команды Python — через `./.venv/Scripts/python.exe` (на Windows голый `python` может быть заглушкой Store).
- Изменения интерфейса проверять в браузере, а не только сборкой: `cd frontend && npm run build`, затем `./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000` из `backend/` и открыть http://127.0.0.1:8000. Для автоматической проверки годится `playwright-core` с системным Edge (`chromium.launch({ channel: "msedge" })`).
- Телефон. Под узкий экран (до 700px, конец `index.css`) подогнаны только верхняя полоса и тренажёр. Дашборд, указатель и страницы проектов на телефоне владелец просила не трогать — их вид там менять нельзя без её просьбы. Изменения тренажёра и полосы проверять и в размере телефона: в playwright — `viewport: { width: 390, height: 844 }, isMobile: true, hasTouch: true`; ничто не должно быть шире экрана, верхняя полоса должна остаться высотой 53px. На телефоне каждая новая карточка тренажёра встаёт сразу под верхнюю полосу, а переключатель колод и счётчик остаются выше, их видно при прокрутке вверх (так просила владелец; `spot`/`placed` в `Trainer.tsx`). Серая подсказка под карточкой там скрыта, а слишком широкие выключные формулы уменьшаются, но не мельче 3/4 (`fitFormulas`).

- Карточки владелец правит прямо на сайте: ✎ на карточке Дашборда, «Изменить» в тренажёре (`CardEditor.tsx`; `PATCH /entities/<slug>`, `POST /entities/<slug>/restore`). Её текст лежит в обычных полях сущности, а текст из JSON — в `entities.edited_fields`. `load_entities` такие поля не перезаписывает и печатает, у каких карточек остался её текст. Поэтому исправление в `extracted/*.json` не дойдёт до сайта в тех полях, которые она меняла, пока она сама не нажмёт «Вернуть исходный текст».

Определения на карточках пишутся формально: каждое условие — формулой с кванторами, без рассуждений вокруг («это самое общее…», «интуиция», «измеряет, насколько…»). Так просила владелец, увидев многословное определение алгебры. Две выключные формулы подряд — одним блоком `aligned`/`gathered`. И коротко: одна карточка — одно понятие, не больше 6–8 строк; нужные ей другие термины — отдельными карточками со ссылками на них, а не пересказом внутри («не пиши простыни», 19/10/2026). То же правило — в генераторе карточек курсов (`RULES` в `artifacts/picks.js`).
- Тренажёр помнит место в каждой колоде («Базовые понятия», каждая статья, «Мой набор») на сервере, чтобы телефон и компьютер продолжали с одной карточки: таблица `deck_progress` хранит карточки, уже пройденные в текущем круге (`/review/decks` в `api/review.py`, `deckKey` в `Trainer.tsx`). Отметки курсов («Модуль пройден», ответы на тесты) сайт больше не хранит: курсы на claude.ai держат их сами (Герстенхабер — в `db` артефакта, 2.6 — в браузере, `mount.ts`: параметр `storage`, по умолчанию `localStorage`). Таблица `course_state` осталась от курсов на сайте со старыми отметками; её никто не читает и не пишет. У сайта один пользователь; всё, что должно быть одинаковым на её устройствах, хранить в базе, а не в браузере.
- Миграции схемы — только через Alembic (`backend/alembic/versions/`), при старте контейнера они применяются сами.
- Деплой: пуш в `master`, затем владелец вручную жмёт **Redeploy** в EasyPanel. Автодеплой не работает (GitHub webhook → 403); это принятое решение, чинить его без её просьбы не нужно. После пуша всегда напоминать про Redeploy.
- Не коммитить, пока не попросили или пока это не часть оговорённой задачи; перед коммитом смотреть `git status`.
