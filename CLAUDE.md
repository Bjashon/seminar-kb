# Seminar KB — памятка для агентов

Двуязычная (RU/EN) база знаний по докладам семинара по неассоциативным алгебрам: определения, теоремы, свойства из статей, связанные между собой; доска статьи; тренажёр; рабочие страницы исследовательских проектов. Отдельный проект, с Draftea не связан ни кодом, ни базой, ни деплоем.

Владелец пишет по-русски — отвечать по-русски. Она сама не программирует: объяснять результат, а не код.

## Устройство

- `backend/` — FastAPI + SQLAlchemy + Alembic. Локально SQLite (`backend/dev.db`), на проде Postgres.
- `frontend/` — React + Vite + MathJax. В проде бэкенд сам раздаёт собранный `frontend/dist`.
- `backend/app/ingestion/extracted/*.json` — весь контент (одна статья = один файл). Общие понятия, не относящиеся ни к одной статье (алгебра Грассмана, теорема Пуанкаре–Биркгофа–Витта), — в `glossary.json` там же.
- `backend/app/ingestion/talks_metadata.json` — снимок метаданных докладов из Notion.
- `data/sources/<код доклада>/` — PDF для панели источника. `data/raw/` — выгрузка Notion, есть только локально, **не трогать**.
- `projects/<slug>/project.md` — страницы исследовательских проектов, вкладка «Статьи» в приложении.

## Добавить статьи

Перед любой работой с контентом прочитать **[docs/adding-talks.md](docs/adding-talks.md)** — там весь процесс, формат JSON и правила, каждое из которых появилось из реальной ошибки. Коротко:

```
cd backend
./.venv/Scripts/python.exe -m app.ingestion.list_talks --season 7 --todo   # что ещё не разобрано
./.venv/Scripts/python.exe -m app.ingestion.validate_extracted             # проверка JSON, 0 errors
./.venv/Scripts/python.exe -m app.ingestion.load_entities                  # загрузить в локальную базу
```

## Исследовательские проекты (вкладка «Статьи»)

Проект — файл `projects/<slug>/project.md`: первая строка `# Название`, дальше обычный markdown с формулами (`$…$`, `$$…$$`), заголовками `##`, списками. Названия понятий из базы в тексте сами становятся ссылками на карточки. Обсуждение идёт в чате, итоги (постановка задачи, решения, следующие шаги, журнал с датами DD/MM/YYYY) записываются в `project.md` и коммитятся. Черновики и выкладки проекта — рядом, в той же папке. Тексты статей пишутся по правилам научных работ, **[docs/papers.md](docs/papers.md)**: в тексте статьи и её TeX никаких заметок и обращений к авторам, замечания — в `zamechaniya.md` рядом. Сейчас есть проекты «Герстенхабер» (`projects/gerstenhaber/`, статья) и «Скобочные тождества (задача 2.6)» (`projects/monomial-identities/`, открытая задача из «Днестровской тетради»; скрипты счёта в `checks/`, им нужен `python-flint`, которого в `.venv` нет; перед работой над задачей читать `START-HERE.md` в папке проекта — там состояние, прочитанная литература и следующий шаг).

Внизу страницы проекта показываются его файлы — блоками, с подписью к каждому файлу. Блоки и подписи описаны в `projects/<slug>/files.json`; новый файл нужно туда вписать, иначе он попадёт в безымянный блок «Остальное». Папки `papers/` и `scratch/` на страницу не выводятся.

Курсы на сайте не показываются (так решила владелец 20/10/2026: без лектора читать неудобно, сайт — в основном для карточек). Курс живёт только на claude.ai; на странице проекта вместо него ссылка «Лекция на claude.ai ↗» (или «Курс…», если в `lecture.json` есть `label`) на `claude_url` из `lecture.json`, в новой вкладке. `lecture.html` (текст курса) и `lecture.json` (тесты, карточки для повторения, глоссарий, данные вычислителей) — исходник копий на claude.ai, их собирают `projects/gerstenhaber/artifact/build_artifact.py` и `projects/monomial-identities/checks/build_artifact.py`. Формулы там пишутся обычным TeX, без своих макросов.

Курс 2.6 собирается из кода `frontend/src/lecture/`: общая часть (оглавление, прогресс, тесты, карточки) — `mount.ts`, вычислители — `labs/`, выбираются полем `labs` в `lecture.json`; новый набор нужно добавить в таблицу `LABS` в `mount.ts`. В сборку сайта этот код не входит. У курса про Герстенхабера вычислители свои, в `artifact/template.html`; `lecture/labs/gerstenhaber.ts` и `lecture/core.ts` — их прежняя версия для сайта. Математика вычислителей проверена: `lecture/core.ts` — на тождествах статьи про Герстенхабера, `lecture/trees.ts` — тестом `projects/monomial-identities/checks/trees.test.mjs` (`node …/trees.test.mjs .` из корня репозитория); если их менять, проверку нужно повторить.

### Курсы на claude.ai и карточки из них

У курсов есть копии на claude.ai (ссылка — `claude_url` в `lecture.json`) с панелью «Спросить лектора». В копиях работает «набор карточек» — общий модуль `artifacts/picks.js`. Владелец выделяет в тексте слово, формулу или утверждение и жмёт «＋ В карточки» — или вписывает своё в поле «Написать самой» в панели набора (фрагмент с пометкой `own` и модулем, который она читала; кнопка набора видна и при пустом наборе). Свой текст Claude формализует и, если в нём ошибка, пишет верную формулировку и одной фразой говорит в «Пояснении», что исправлено. В наборе Claude (capability `sample`) пишет из фрагментов карточки: формальная формулировка плюс абзац «*Пояснение.*». До отправки карточку можно исправить прямо в наборе («Изменить»: вид, название, текст с предпросмотром, английская версия); отправленные помечаются (`sent` в записи набора, на всех устройствах) и в следующую отправку не попадают; карточки удаляются по одной, вместе со своими фрагментами или все отправленные разом (кнопка срабатывает со второго нажатия); «Сделать карточки» не трогает отправленные и исправленные и берёт только остальные фрагменты. У карточек набора есть `id`. «Отправить на сайт» открывает `<сайт>/#import=<код>`, «Скопировать код» — вставка через кнопку «Карточки из курса» на странице проекта.

- Сайт сначала показывает карточки (`ImportCards.tsx`), а добавляет только по кнопке: `POST /cards` (`api/cards.py`), с пометкой `entities.made_by_user`. Куда — выбирает она:
  - в колоду курса (псевдодоклад `proj_<slug>`, при нужде создаётся);
  - в «Мой набор» (без колоды, с закладкой);
  - в любую готовую колоду;
  - в свою новую тему — доклад-колода `my_<n>` с её названием, в списке тренажёра подписан «моя тема»; то же название ещё раз — та же тема. Свои темы и колоды курсов (`proj_`) стоят в «По статьям» первыми, блоком «Мои темы и курсы»: без даты они иначе уходили в самый низ, и владелец их не находила.
- `load_entities` такие карточки не трогает. Тренажёр берёт их любого вида, включая теоремы. Удаляются они, как и все карточки, мягко (см. ниже). Карточка, присланная туда же ещё раз с тем же названием и текстом, что у удалённой, возвращает удалённую, а не дублирует её.
- Набор, адрес сайта и прогресс курса копия хранит в своей `db` (`data/users/<id>/picks`, `.../progress`), поэтому нужны capabilities `sample`, `db`, `user`.
- Свои TeX-сокращения курса (`\Z`, `\rp{…}` из конфигурации MathJax) модуль раскрывает: на сайте их нет.

Правила владелец задавала по ходу, их держать: поля узкие, слайды прижаты к верху (`t`); слайд раскрывается логическими кусками (`\onslide`, а всё с цветной заливкой — через `\only`, иначе заливка видна раньше времени); формулы — выключные, в строку почти никогда; несколько формул — столбиком, по одной на строке, выровнены по «=» (две группы рядом тоже можно; тесно связанные короткие, как $V=V_0\oplus V_1$ и $V_iV_j\subseteq V_{i+j}$, — в одну строку с большими отступами); название правила — серым в скобках справа на строке формулы (`\nm{…}`: «(суперкоммутативность)», «(правило Лейбница)»), подпись группы формул — сбоку, по центру группы, без фигурной скобки; текста на слайде минимум, только нужное и полезное (04/11/2026); в примере условие (что дано) — в сером заголовке `exbox`, в теле — как оно применяется, сначала применение правила, потом результат; то, что из условия выводится (как $\{p,q\}=1$ из формулы скобки), считается в теле, а не выдаётся за условие; почему условие годится (почему это скобка) — подсказкой `\ftip` у формулы, без серых подписей и без выкладок на слайде; определения — полные, нормальным текстом, формально корректно: что за объект, какие операции, «для всех однородных $a,b,c$», затем формулы; основная конструкция (как $\mathbb Z_2$-градуировка у супералгебры) — в самом определении, а не серой подписью; если полное определение не помещается вместе с примером, пример — на соседнем слайде «…: пример» (04/11/2026: так она выбрала из двух вариантов; текста по-прежнему минимум, но не в ущерб определению); номера формул: (1)–(8) — как в статье, вспомогательные формулы доклада — по частям, (1.1)–(1.6) в части 1; ссылка на номер — `\fn{1.2}`, куда она ведёт (слайд и шаг, где формула уже видна), задаёт таблица `\deffn` в преамбуле; знак в суперформулах подписывается самим правилом: «(правило Кошуля: $d\,a\to(-1)^{p|a|}\,a\,d$)»; слева на слайде зелёная колонка `sidebox` вплотную к полосе: только формулы, уже определённые на предыдущих слайдах, мельче основного текста, номер «(5)» зелёным и он же ссылка на слайд формулы (`\sromn{1.2}{…}`; у `\sform` (1)–(5) ведут на определение 1, (7), (8) — на их слайд), перенос каскадом, они появляются вместе с куском, которому нужны; если на слайде есть ссылка на номер, эта формула должна стоять в колонке; ширина колонки — по формулам (`\sidecol[0.165]` + `\maincol[0.815]`), стрелки в углу колонки нет (убрана 04/11/2026; все формулы по порядку — на страницах «Формулы доклада», A8–A14); полоса «План» (`\framesubtitle{\planbar{k}}`) вместо зелёной черты — только на слайдах, где доказывается вспомогательное, и после слайда «План доказательства», который показывает по этапу за шаг. В PDF есть ссылки (`\go{метка}{текст}` — зелёный текст, метки кадров `[label=…]`; `\ax{5}` — на определение 1; стрелки ◀ ▶ в нижней строке — соседние слайды, название — на план) и всплывающие подсказки `\tip{текст}{подсказка}` через pdfcomment (видны в Acrobat, Foxit, Chrome, Firefox; не в Preview и SumatraPDF; в них только текст, символы Юникода можно); подсказка с формулами — `\ftip[сдвиг]{id}{термин}{текст}{формулы}`: при наведении тот же текст, а щелчок по серому треугольнику после термина показывает над ним рамку со свёрстанными формулами (слой PDF, пакет ocgx2; Acrobat, Foxit, PDF-XChange, в браузерах — не всегда; пакета tooltip в облачной сборке нет). Сдвиг рамки отсчитывается от конца термина; рамка должна целиком помещаться в слайд — проверять копией с открытыми слоями (в `\ftip` последний аргумент `ocg` `{0}` → `{1}`, плюс опция `handout`, файл в `scratch/`) и картинками её страниц. В подсказках не отождествлять обозначения, которые дальше в докладе значат разное (квадратная скобка — скобка супералгебры Ли и слова $[u,v]$). pdfcomment занимает `\hl` (поэтому выделение — `\hlt`) и тянет два предупреждения пакетов — они обезврежены в преамбуле (soulutf8, `\hypersetup`), не убирать. LaTeX на компьютере нет: все документы проекта (доклад, статья, перевод, макеты) собираются в облаке прямо на месте, `node tools/texbuild.mjs projects/gerstenhaber/Gerstenhaber_doklad.tex` из корня репозитория; PDF и лог ложатся рядом с .tex. Статья — с `--engine xelatex` (так собраны все её PDF), перевод и доклад выбирают XeLaTeX сами. Лог должен быть без ошибок и без новых предупреждений: `grep -i -E "overfull|underfull|warning|^!" <имя>.log`. Копий в `Documents/latex` не делать: владелец хранит и ведёт всё в seminar-kb (04/11/2026). Макеты и черновики — в `projects/gerstenhaber/scratch/`, она не в git. После сборки страницы рисуются в PNG через pdf.js в Chrome (скрипт `render.mjs`, живёт в scratchpad сессии: pdfjs-dist + playwright-core, `chromium.launch({ channel: "chrome" })`; Edge на этой машине не запускается). Если слайды добавились или убрались, часть III (`<figure class="slide">` в `lecture.html`) перенумеровать.

Как писать текст курса (владелец требовала это жёстко, 20/10/2026): курс рассказывает, а не перечисляет. Каждое понятие определено до первого использования; каждая выкладка — по строкам, с правилом на каждом шаге; примеры досчитаны до конца; никаких «очевидно», «как известно», «аналогично», «запомни»; короткие абзацы, без сплошных блоков текста. В модуле сначала вся теория, вопросы и задачки (с решениями) — в конце. Варианты ответов в тестах движок не перемешивает, поэтому верный ответ ставить на разные места. Ловушка MathJax: «[» в начале строки сразу после `\begin{aligned}` или после `\\` читается как параметр и пропадает — писать `{}[`. Длинную формулу (шире примерно 350 точек) писать выключной, `$$…$$`: строчную MathJax не переносит и не прокручивает, и она растягивает всю страницу на телефоне; выключные прокручиваются сами (проверка — ширина страницы 390 при `viewport` 390, в playwright с `isMobile`). В длинных выкладках ключевые места подсвечиваются маркером (владелец попросила 03/11/2026, модули 14–15): в формуле `\hl{…}` (жёлтый — главное), `\hlb{…}` (синий), `\hlc{…}` (розовый) — внутри без `&` и `\\`, знак перед членом снаружи; сразу под формулой подпись `<p class="look"><b>Куда смотреть.</b> <mark class="a">Жёлтым</mark> — …</p>` (`mark.b`, `mark.c` — остальные цвета), одна–три фразы. Цвета заданы в шаблоне для обеих тем (`--hl-a/b/c`), на карточки набора пометки не попадают (`unwrap` в `picks.js`).

## Проверка и деплой

- Команды Python — через `./.venv/Scripts/python.exe` (на Windows голый `python` может быть заглушкой Store).
- Изменения интерфейса проверять в браузере, а не только сборкой: `cd frontend && npm run build`, затем `./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000` из `backend/` и открыть http://127.0.0.1:8000. Для автоматической проверки годится `playwright-core` с системным Chrome (`chromium.launch({ channel: "chrome" })`; Edge с 29/10/2026 не запускается в headless).
- Телефон. Под узкий экран (до 700px, конец `index.css`) подогнаны только верхняя полоса и тренажёр. Дашборд, указатель и страницы проектов на телефоне владелец просила не трогать — их вид там менять нельзя без её просьбы. Изменения тренажёра и полосы проверять и в размере телефона: в playwright — `viewport: { width: 390, height: 844 }, isMobile: true, hasTouch: true`; ничто не должно быть шире экрана, верхняя полоса должна остаться высотой 53px. На телефоне каждая новая карточка тренажёра встаёт сразу под верхнюю полосу, а переключатель колод и счётчик остаются выше, их видно при прокрутке вверх (так просила владелец; `spot`/`placed` в `Trainer.tsx`). Серая подсказка под карточкой там скрыта, а слишком широкие выключные формулы уменьшаются, но не мельче 3/4 (`fitFormulas`).

- Карточки владелец правит прямо на сайте: ✎ на карточке Дашборда, «Изменить» в тренажёре (`CardEditor.tsx`; `PATCH /entities/<slug>`, `POST /entities/<slug>/restore`). Её текст лежит в обычных полях сущности, а текст из JSON — в `entities.edited_fields`. `load_entities` такие поля не перезаписывает и печатает, у каких карточек остался её текст. Поэтому исправление в `extracted/*.json` не дойдёт до сайта в тех полях, которые она меняла, пока она сама не нажмёт «Вернуть исходный текст».
- Удалить владелец может любую карточку: корзина на карточке Дашборда, «Удалить» в тренажёре (`DELETE /entities/<slug>`). Удаление мягкое: ставится `entities.deleted_at`, и карточка пропадает отовсюду — указатель, поиск, доски, колоды и счётчики тренажёра, ссылки в текстах других карточек. `load_entities` её не возвращает и печатает, какие карточки остались удалёнными. Вернуть — плашкой «Вернуть» сразу после удаления или потом в тренажёре, «Удалённые» (`POST /entities/<slug>/undelete`). Чтобы убрать карточку из контента насовсем, её удаляют из `extracted/*.json`. Новый запрос, который перечисляет карточки, должен отбрасывать удалённые (`Entity.deleted_at.is_(None)`).

Определения на карточках пишутся формально: каждое условие — формулой с кванторами, без рассуждений вокруг («это самое общее…», «интуиция», «измеряет, насколько…»). Так просила владелец, увидев многословное определение алгебры. Две выключные формулы подряд — одним блоком `aligned`/`gathered`. И коротко: одна карточка — одно понятие, не больше 6–8 строк; нужные ей другие термины — отдельными карточками со ссылками на них, а не пересказом внутри («не пиши простыни», 19/10/2026). То же правило — в генераторе карточек курсов (`RULES` в `artifacts/picks.js`).
- Тренажёр помнит место в каждой колоде («Базовые понятия», каждая статья, «Мой набор») на сервере, чтобы телефон и компьютер продолжали с одной карточки: таблица `deck_progress` хранит карточки, уже пройденные в текущем круге (`/review/decks` в `api/review.py`, `deckKey` в `Trainer.tsx`). Отметки курсов («Модуль пройден», ответы на тесты) сайт больше не хранит: курсы на claude.ai держат их сами (Герстенхабер — в `db` артефакта, 2.6 — в браузере, `mount.ts`: параметр `storage`, по умолчанию `localStorage`). Таблица `course_state` осталась от курсов на сайте со старыми отметками; её никто не читает и не пишет. У сайта один пользователь; всё, что должно быть одинаковым на её устройствах, хранить в базе, а не в браузере.
- Миграции схемы — только через Alembic (`backend/alembic/versions/`), при старте контейнера они применяются сами.
- Деплой: пуш в `master`, затем владелец вручную жмёт **Redeploy** в EasyPanel. Автодеплой не работает (GitHub webhook → 403); это принятое решение, чинить его без её просьбы не нужно. После пуша всегда напоминать про Redeploy.
