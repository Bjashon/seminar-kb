# Как добавлять статьи в базу

Инструкция для агентов (и людей): весь путь от доклада в Notion до карточек, доски и тренажёра на проде. Каждое правило здесь появилось из реальной ошибки — не пропускайте их.

Все команды — из папки `backend/`, через Python из виртуального окружения: `./.venv/Scripts/python.exe -m ...` (на Windows голый `python` может оказаться заглушкой из Microsoft Store).

## 0. Что где лежит

- `data/raw/export/` — полная выгрузка Notion: CSV со всеми докладами и PDF статей. **Не в git и не на сервере, есть только на машине владельца.** Ничего там не удалять и не перемещать.
- `backend/app/ingestion/extracted/<файл>.json` — разобранная статья: все её определения, теоремы, свойства и бриф. Это главный источник контента. Один файл = одна статья.
- `backend/app/ingestion/talks_metadata.json` — снимок метаданных всех докладов (название, дата, сезон, файлы PDF). Нужен, потому что выгрузки Notion на сервере нет.
- `data/sources/<episode_code>/<pdf>` — PDF, которые открывает панель «источник» в приложении.
- При каждом запуске контейнера (см. `Dockerfile`) выполняется: `alembic upgrade head` → `load_talks_metadata` → `load_entities` → сервер. То есть всё, что закоммичено в JSON, само попадает в базу при деплое.

## 1. Решить, что разбирать

```
python -m app.ingestion.list_talks --season 7 --todo
python -m app.ingestion.list_talks --from 2026-10-01 --to 2026-12-31
```

Скрипт показывает каждый доклад с датой, кодом, файлами статей и статусом: `готово: <json>`, `НОВАЯ` или `только слайды`.

Правила выбора:
- **Одна статья на несколько докладов.** Если у докладов (Part I/II/III) один и тот же PDF, это одна статья: пишем один JSON с `episode_code` любого из них (обычно того, что стоит в плане разбора). Доска и тренажёр сами склеят части по имени PDF и покажут все даты.
- **Та же статья в другой версии.** Журнальная версия препринта, уже разобранного раньше (например, arXiv 2020 и J. Algebra 2023), — не разбирать заново. Сверить авторов и название на первой странице PDF, затем дописать имя нового файла в `also_covers_documents` того JSON, который её уже покрывает. Тогда `list_talks` перестанет считать её новой.
- **Один код — разные статьи.** Notion иногда даёт двум докладам один код (21/09 и 28/09 оба `s07_ep35`, Part I и Part II, но PDF разные). Тогда два JSON с одним `episode_code` и полем `talk_title_hint`, которым заканчивается название нужного доклада (`"Part I"` / `"Part II"`). Без него загрузчик остановится с ошибкой.
- **Слайды** (`Presentation`) не разбираем — только статьи.

## 2. Прочитать статью

- PDF: `data/raw/export/Private & Shared/Asian-European seminar on non-associative algebras/Seminar/<папка доклада>/`.
- Инструмент Read с параметром `pages` (не больше 20 страниц за раз). Для сканов и русских статей удобнее извлечь текст PyMuPDF (`pip install pymupdf`, `import pymupdf`).
- Сразу определить **сдвиг страниц**: `source.page` — это номер страницы **внутри PDF-файла**, а не печатный номер в журнале. Если в колонтитуле первой страницы стоит «141», а в файле она первая, сдвиг −140. Ссылка на источник открывает PDF на `#page=<source.page>`.

## 3. Формат JSON

Образцы: `extracted/s07_ep36.json`, `extracted/s07_ep35_part1.json`.

```json
{
  "episode_code": "s07_ep42",
  "talk_title_hint": "Part I",
  "source_language": "en",
  "source_note": "Что извлечено и что сознательно пропущено — для следующего агента.",
  "bibliography": "Авторы — «Название» (журнал, год, doi)",
  "brief_ru": "…",
  "brief_en": "…",
  "source_document": "2026_-_Имя_файла.pdf",
  "also_covers_documents": ["другая_версия_той_же_статьи.pdf"],
  "entities": [
    {
      "kind": "definition",
      "slug": "novikov-algebra",
      "title_en": "Novikov algebra",
      "title_ru": "Алгебра Новикова",
      "aliases": ["Gelfand-Dorfman algebra"],
      "statement_en": "An algebra is a **Novikov algebra** if …\n$$(xy)z=(xz)y$$",
      "statement_ru": "Алгебра называется **алгеброй Новикова**, если …\n$$(xy)z=(xz)y$$",
      "proof_en": null,
      "proof_ru": null,
      "depends_on": ["Algebra (over a field)"],
      "topic": "Алгебры Новикова",
      "topic_order": 15,
      "is_foundational": false,
      "source": { "label": "Определение 2.1", "document": "2026_-_Имя_файла.pdf", "page": 3 }
    }
  ]
}
```

`talk_title_hint`, `also_covers_documents`, `aliases`, `proof_*`, `is_foundational` — необязательные.

## 4. Правила содержания

1. **`kind` только `definition`, `theorem` или `property`.** Другие виды интерфейс не умеет показывать. Открытые проблемы пропускаем (или описываем в брифе словами).
2. **Никакого LaTeX в заголовках.** `title_ru`/`title_en` выводятся как обычный текст, без MathJax: никаких `$` и `\`. Нужна формула — Unicode («Z₂», «n-алгебра Ли», «K3»).
3. **Только стандартные макросы MathJax.** `\llbracket`, `\rrbracket`, `\coloneqq` и прочее из mathtools/stmaryrd отрисуются красной ошибкой. Вместо двойных скобок — ⟦ ⟧.
4. **Не стеной текста.** Абзацы разделять `\n\n`. Каждую ключевую формулу или тождество — отдельной строкой в `$$…$$`. Короткие предложения. Уровень — студент 3 курса. Списки — `1.`, `2.` с новой строки.
5. **Первый жирный фрагмент — определяемый термин.** В каждом определении в `statement_ru` (и `statement_en`) первым `**…**` должен идти именно термин: тренажёр на втором уровне прячет его и просит вписать.
6. **`depends_on` — точные `title_en`.** Ссылка ищется по точному совпадению с `title_en` или алиасом другой сущности (без учёта регистра). Опечатка — и связь молча пропадёт. Список существующих названий:
   `grep -ho '"title_en": "[^"]*"' app/ingestion/extracted/*.json | sort -u`
7. **Не дублировать понятия.** Прежде чем определять что-то базовое (алгебра Ли, дифференцирование, ассоциатор, идеал…), поискать его в базе и сослаться. Если несколько агентов работают параллельно, заранее распределить, кто какое общее понятие заводит, с точными `title_en`.
8. **Слаги** — латиница в kebab-case, уникальные во всех файлах. Одинаковый слаг в двух файлах — загрузчик молча перезапишет одну сущность другой.
9. **Калибровка.** Брать: все определения, без которых не сформулировать результаты, включая «кирпичики», которых ещё нет в базе; главные теоремы — с сокращённым доказательством, если оно короткое или у него ясная ключевая идея; леммы, осмысленные сами по себе, — как `theorem`/`property`. Не брать: чисто технические леммы-леса (упомянуть в `source_note`). Большие классификационные таблицы — одним `property` с итогом, а не по сущности на каждую алгебру. Обычно 8–20 сущностей на статью.
10. **`is_foundational: true`** — только для общих учебных понятий (ассоциатор, дифференцирование алгебры, группа Ли), не для понятий конкретной статьи. Они попадают в режим тренажёра «Базовые понятия».
11. **Тема.** `topic` — русское название раздела, `topic_order` — его порядковый номер; все сущности статьи обычно в одной теме. Существующие темы: `grep -h '"topic"' app/ingestion/extracted/*.json | sort | uniq -c`. Новая тема — следующий свободный номер.
12. **Русский текст пишется так же тщательно, как английский** — владелец читает в первую очередь его.
13. **Честность.** Если в статье опечатка или пробел в доказательстве — исправить и явно пометить это на карточке. Если доказательство дописано не по статье — так и написать.

## 5. Бриф (`brief_ru` / `brief_en`)

Первая карточка на доске статьи: «Кратко о статье».
- 1–2 фразы: какой вопрос решает статья и зачем.
- Пустая строка, затем нумерованный список (`1.`, `2.` — каждый пункт с новой строки) из 3–6 главных результатов, по 1–2 коротких предложения. Маркеры `-` здесь не использовать.
- Формулы — только строчные `$…$`, без `$$` и без жирного.
- Где звучит естественно, называть понятия **точными** `title_ru` / `title_en` из базы: такие совпадения превращаются в ссылки на карточки. Грамматику ради этого не ломать.
- До ~120 слов на язык.

## 6. Положить PDF

Скопировать каждый PDF, на который ссылается `source.document`, в `data/sources/<episode_code>/` (именно в папку кода этого JSON). Иначе ссылка на источник вернёт 404. Имена файлов не менять.

## 7. Новые доклады (которых нет в `talks_metadata.json`)

Если доклад появился в Notion после последнего снимка, сначала обновить выгрузку (Notion → Export → Markdown & CSV, распаковать в `data/raw/export/` **через Python `zipfile`**: `unzip` из git-bash портит кириллические имена), затем пересобрать снимок на **временной** базе (на `dev.db` так делать нельзя — `parse_export` вставляет доклады повторно):

```
export DATABASE_URL="sqlite:///./tmp_export.db"
./.venv/Scripts/python.exe -m alembic upgrade head
./.venv/Scripts/python.exe -m app.ingestion.parse_export
./.venv/Scripts/python.exe -m app.ingestion.dump_talks_metadata
rm tmp_export.db; unset DATABASE_URL
git diff --stat app/ingestion/talks_metadata.json   # должны добавиться только новые доклады
```

## 8. Проверить

```
./.venv/Scripts/python.exe -m app.ingestion.validate_extracted          # 0 errors обязательно
./.venv/Scripts/python.exe -m alembic upgrade head
./.venv/Scripts/python.exe -m app.ingestion.load_talks_metadata
./.venv/Scripts/python.exe -m app.ingestion.load_entities               # не должно быть "Unresolved dependencies"
```

Валидатор проверяет всё из разделов 4–6: виды, заголовки, макросы, парность `$`, связи, дубли слагов, наличие PDF и что номера страниц не выходят за пределы файла (нужен PyMuPDF).

Посмотреть глазами: собрать фронтенд (`cd ../frontend && npm run build`), запустить `./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000` (сервер сам раздаёт собранный фронтенд) и открыть http://127.0.0.1:8000 → Тренажёр → По статьям → «Доска». Проверить: бриф первой карточкой, формулы отрисованы, ссылки кликаются, «источник» открывает нужную страницу PDF.

## 9. Закоммитить и задеплоить

- Закоммитить JSON, PDF из `data/sources/`, при необходимости `talks_metadata.json`. Запушить в `master`.
- Автодеплой на EasyPanel не работает (webhook GitHub → EasyPanel отвечает 403). После пуша владелец нажимает **Redeploy** в EasyPanel вручную — предупредить её об этом.
- Загрузка в базу на сервере произойдёт сама при старте контейнера.

## 10. Параллельный разбор несколькими агентами

Удобно раздать по одной статье на агента. В задании каждому дать:
- код доклада, дату, путь к PDF, имя выходного файла, `topic` и `topic_order`;
- ссылку на этот документ (разделы 2–6) и на файлы-образцы;
- **список общих понятий с точными `title_en`: какие он заводит сам, а на какие только ссылается** (иначе два агента создадут одно понятие дважды);
- запрет: не запускать `load_entities` (одна общая SQLite-база, параллельные записи конфликтуют), не коммитить, не трогать чужие файлы;
- требование прогнать `validate_extracted` на своём файле и отчитаться: число сущностей по видам, слаги, ссылки на чужие понятия, в чём не уверен.

После всех агентов главный агент один раз прогоняет раздел 8 целиком, сам проверяет пару карточек на смысл и коммитит.

## 11. Подводные камни окружения (Windows)

- Консоль Windows по умолчанию в cp1252: `print` кириллицы падает с `UnicodeEncodeError`. В своих скриптах — `sys.stdout.reconfigure(encoding="utf-8")`. Иногда кириллица и «é» в выводе терминала выглядят кракозябрами, хотя в файле и в базе всё верно: сверять данные через Python, а не глазами по выводу `curl`.
- `uvicorn --reload` на Windows оставляет дочерние процессы, которые держат порт 8000 и отдают старый код. Перед запуском проверить порт (`Get-NetTCPConnection -LocalPort 8000`) и убить владельца. Для проверок запускать без `--reload`.
- Не перемещать и не переименовывать папку проекта, пока она открыта в VS Code: встроенный git держит `.git`, и перенос обрывается на полпути.
